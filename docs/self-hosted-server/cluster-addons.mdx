## Cluster Addons Installation

Yorkie provides a set of cluster addons to help you monitor and manage Yorkie cluster.

This guide will walk you through the process of installing Yorkie cluster addons on your Kubernetes cluster.

Currently, Yorkie addons include:

- [Prometheus](https://prometheus.io/) for collecting metrics from Yorkie cluster.
- [Grafana](https://grafana.com/) for monitoring Yorkie cluster via Grafana dashboard.
- [Loki](https://grafana.com/oss/loki/) for logging aggregation.
- [MongoDB exporter](https://github.com/percona/mongodb_exporter) (optional) for collecting MongoDB metrics.
- [ArgoCD](https://argo-cd.readthedocs.io/) for managing Yorkie cluster via GitOps.
- [Kafka](https://kafka.apache.org/) for analytics of usage of Yorkie cluster.
- [StarRocks](https://starrocks.com/) for analytics of usage of Yorkie cluster.

### Prerequisites

This guide assumes that you have installed Yorkie cluster on your Kubernetes cluster with Helm chart.
If you haven't installed Yorkie cluster, follow guides for deploying Yorkie cluster on Kubernetes with Helm Charts on various platforms.

- [Minikube Installation](/docs/self-hosted-server/minikube): Guide to install Yorkie cluster on Minikube.
- [AWS EKS Installation](/docs/self-hosted-server/aws-eks): Guide to install Yorkie cluster on AWS EKS.

### Install Yorkie Monitoring with Helm chart

You can install Yorkie monitoring addon to collect and monitor Yorkie metrics and logs.
Yorkie monitoring addons include Prometheus, Grafana, and Loki to collect metrics and logs from Yorkie cluster.

Install Yorkie monitoring addon with the following command:

```bash
$ helm install yorkie-monitoring yorkie-team/yorkie-monitoring -n monitoring --create-namespace
```

If you are using AWS EKS, use the following command instead:

```bash
$ helm install yorkie-monitoring yorkie-team/yorkie-monitoring -n monitoring --create-namespace \
    --set ingress.ingressClassName=alb \
    --set ingress.hosts.enabled=true \
    --set ingress.hosts.apiHost={YOUR_API_DOMAIN_NAME} \
    --set ingress.awsAlb.enabled=true \
    --set ingress.awsAlb.certArn={YOUR_CERTIFICATE_ARN}
```

Replace `{YOUR_API_DOMAIN_NAME}` with your domain name.
Also, replace `{YOUR_CERTIFICATE_ARN}` with your certificate ARN.

This will install `yorkie-monitoring` release.

<Alert status="info">You can also set other Helm chart configuration options. For more information about Helm chart configuration, see [Yorkie Monitoring Helm Chart Configuration](https://github.com/yorkie-team/yorkie/tree/main/build/charts/yorkie-monitoring#configuration).</Alert>

#### Monitoring options

The monitoring chart also has the following options:

- `monitoring.yorkieName` and `monitoring.yorkieNamespace`: the name and namespace of the Yorkie cluster to scrape (default `yorkie` for both). They must match `yorkie.name` and `yorkie.namespace` of your `yorkie-cluster` release, or Prometheus finds no Yorkie metrics.
- `monitoring.enableEnhancements`: also deploy Alertmanager and kube-state-metrics, and scrape Kubernetes components such as the API server, kubelet and etcd. They are off by default.
- `mongodbExporter.enabled`: deploy [MongoDB exporter](https://github.com/percona/mongodb_exporter) with a ServiceMonitor and a MongoDB dashboard in Grafana. Give it the MongoDB connection URI with `mongodbExporter.mongodb.uri`, or with `mongodbExporter.mongodb.existingSecret`, the name of a Secret in the `monitoring` namespace that holds the URI under the key `mongodb-uri`.

### Install ArgoCD with Helm chart

You can install ArgoCD to perform continuous delivery of Yorkie cluster with GitOps.
We use the upstream [argo/argo-cd](https://github.com/argoproj/argo-helm/tree/main/charts/argo-cd) Helm chart.

First, add the Argo Helm repository:

```bash
$ helm repo add argo https://argoproj.github.io/argo-helm
$ helm repo update
```

Install ArgoCD with the following command:

```bash
$ helm install argo-cd argo/argo-cd -n argocd --create-namespace \
    --set configs.params."server.insecure"=true \
    --set configs.params."server.rootpath"=/argocd
```

If you are using AWS EKS with ALB, add the ingress configuration:

```bash
$ helm install argo-cd argo/argo-cd -n argocd --create-namespace \
    --set configs.params."server.insecure"=true \
    --set configs.params."server.rootpath"=/argocd \
    --set server.ingress.enabled=true \
    --set server.ingress.ingressClassName=alb \
    --set server.ingress.hostname={YOUR_API_DOMAIN_NAME} \
    --set server.ingress.path=/argocd/ \
    --set server.ingress.annotations."alb\.ingress\.kubernetes\.io/scheme"=internet-facing \
    --set server.ingress.annotations."alb\.ingress\.kubernetes\.io/certificate-arn"={YOUR_CERTIFICATE_ARN} \
    --set server.ingress.annotations."alb\.ingress\.kubernetes\.io/group\.name"={YOUR_API_DOMAIN_NAME} \
    --set 'server.ingress.annotations.alb\.ingress\.kubernetes\.io/listen-ports=[{"HTTP": 80}\, {"HTTPS": 443}]'
```

Replace `{YOUR_API_DOMAIN_NAME}` with your domain name.
Also, replace `{YOUR_CERTIFICATE_ARN}` with your certificate ARN.
The `group.name` annotation lets ArgoCD share the ALB that Yorkie cluster and Yorkie monitoring use for the same domain, instead of provisioning another one.

<Alert status="info">For more information about Helm chart configuration, see [argo-cd chart documentation](https://github.com/argoproj/argo-helm/tree/main/charts/argo-cd).</Alert>

You will connect the Yorkie addons to ArgoCD with the ArgoCD Applications chart in [Connect Yorkie addons to ArgoCD](#connect-yorkie-addons-to-argocd), after all addons are installed.

You can get the initial admin password with the following command:

```bash
$ kubectl -n argocd get secret argocd-initial-admin-secret -o jsonpath="{.data.password}" | base64 -d
```

It will take a few minutes for pods to be ready, so wait until all pods are ready.
You can check the status of pods with the following command:

```bash
$ kubectl get pods -n argocd --watch
```

### Connect Yorkie cluster to Yorkie analytics

Now you have Yorkie analytics installed, you can connect Yorkie cluster to Yorkie analytics.
You need to set up the following arguments in your Yorkie cluster:

```bash
helm upgrade yorkie-cluster yorkie-team/yorkie-cluster --namespace yorkie \
  --set yorkie.args.kafkaAddresses=yorkie-analytics-kafka.analytics.svc.cluster.local:9092 \
  --set yorkie.args.kafkaWriteTimeout=5s \
  --set yorkie.args.starrocksDSN="root:@tcp(kube-starrocks-fe-search.analytics.svc.cluster.local:9030)/yorkie" \
  --set yorkie.args.secretKey="$YORKIE_SECRET_KEY" \
  --set yorkie.args.clusterSecret="$YORKIE_CLUSTER_SECRET" \
  --set mongodb.credentials.databaseAdmin.password="$MONGO_DB_ADMIN_PASSWORD" \
  --set mongodb.credentials.userAdmin.password="$MONGO_USER_ADMIN_PASSWORD" \
  --set mongodb.credentials.clusterAdmin.password="$MONGO_CLUSTER_ADMIN_PASSWORD"
```

The server sends events to the topics `user-events`, `document-events`, `client-events`, `channel-events` and `session-events`, which are the topics the analytics chart creates. If you rename a topic, change it on both sides: `yorkie.args.kafka{User,Document,Client,Channel,Session}EventsTopic` in Yorkie cluster, and the topic names in the `yorkie-analytics` values.

<Alert status="warning">Pass the **same** credentials you used to install Yorkie cluster: without them the upgrade fails to render, and a new signing key logs every admin user out. If they are no longer in your shell, `helm get values yorkie-cluster --namespace yorkie` prints the values the release was installed with, and [Upgrading Chart](https://github.com/yorkie-team/yorkie/tree/main/build/charts/yorkie-cluster#upgrading-chart) shows how to read them back from the cluster's Secrets. `helm upgrade` also resets omitted values to the chart defaults, so add any other values your release uses, such as the ingress settings from the AWS EKS guide. If the release was installed with chart v0.7.24 or earlier, which required neither secret and defaulted the MongoDB passwords to values the chart now rejects, follow the upgrade notes in [Upgrading Chart](https://github.com/yorkie-team/yorkie/tree/main/build/charts/yorkie-cluster#upgrading-chart) before running this command, rather than generating new MongoDB passwords.</Alert>

If clients are connected to Yorkie cluster with `userID`([Measuring MAU](/docs/sdks/js-sdk#measuring-mau)), you can see the user events are collected in StarRocks database.


#### Long-retention project stats (optional)

The analytics init job also creates daily summary tables (`sum_*_hll_daily`), the `rl_session_daily` rollup and the materialized views that fill them. Set `yorkie.args.starrocksSummaryEnabled=true` in Yorkie cluster to serve project stats history from those tables instead of the raw event tables.
Enable it only once the summary tables hold your existing events and `SELECT 1 FROM rl_session_daily [_SYNC_MV_] LIMIT 1` returns rather than errors; until then, the sessions stats fall back to a slower index.
For the details, see [Project Stats Long Retention](https://github.com/yorkie-team/yorkie/blob/main/docs/design/project-stats-long-retention.md).

<Alert status="warning">When you upgrade, upgrade `yorkie-analytics` first, and roll out Yorkie cluster only after the `rl_session_daily` query above returns. The init job waits only up to two minutes for the rollup to build, so a completed job does not mean that the rollup is ready.</Alert>

### Connect Yorkie addons to ArgoCD

Now that all addons are installed, you can connect them to ArgoCD for GitOps-based continuous delivery.

Create an `apps-values.yaml` file that defines ArgoCD Applications for each Yorkie addon:

```yaml
# apps-values.yaml
applications:
  yorkie-cluster:
    namespace: argocd
    project: default
    sources:
      - repoURL: https://yorkie-team.github.io/yorkie/helm-charts
        chart: yorkie-cluster
        targetRevision: {{YORKIE_VERSION}}
        helm:
          valueFiles:
            - $values/k8s/cluster/values.yaml
      - repoURL: https://github.com/your-org/your-devops-repo.git
        targetRevision: main
        ref: values
    destination:
      server: https://kubernetes.default.svc
      namespace: yorkie

  yorkie-monitoring:
    namespace: argocd
    project: default
    sources:
      - repoURL: https://yorkie-team.github.io/yorkie/helm-charts
        chart: yorkie-monitoring
        targetRevision: 0.7.7
        helm:
          valueFiles:
            - $values/k8s/monitoring/values.yaml
      - repoURL: https://github.com/your-org/your-devops-repo.git
        targetRevision: main
        ref: values
    destination:
      server: https://kubernetes.default.svc
      namespace: monitoring

  yorkie-analytics:
    namespace: argocd
    project: default
    source:
      repoURL: https://yorkie-team.github.io/yorkie/helm-charts
      chart: yorkie-analytics
      targetRevision: 0.7.26
    destination:
      server: https://kubernetes.default.svc
      namespace: analytics
```

Replace `your-org/your-devops-repo` with your GitOps repository that contains the Helm values files.

<Alert status="info">Each chart has its own version, so `targetRevision` differs per chart: `yorkie-cluster` follows the Yorkie server version, while `yorkie-monitoring` and `yorkie-analytics` are released separately. Run `helm search repo yorkie-team -l` to list the chart versions you can use.</Alert>

<Alert status="warning">ArgoCD renders `yorkie-cluster` from `k8s/cluster/values.yaml`, so that file must set the same required credentials as `helm install`: the signing key, the cluster secret and the three MongoDB passwords. To keep the signing key and the cluster secret out of Git, store them in a Secret you manage and reference it with `yorkie.args.secretKeyExistingSecret` and `yorkie.args.clusterSecretExistingSecret`. The chart has no such option for the MongoDB passwords, so the values file carries them in plain text: keep that repository private and limit who can read it. See [Yorkie Cluster Helm Chart](https://github.com/yorkie-team/yorkie/tree/main/build/charts/yorkie-cluster#admin-token-signing-key-required) for details.</Alert>

Install the Applications chart:

```bash
$ helm install argocd-apps argo/argocd-apps -n argocd -f apps-values.yaml
```

<Alert status="info">For more information about the argocd-apps chart, see [argocd-apps chart documentation](https://github.com/argoproj/argo-helm/tree/main/charts/argocd-apps).</Alert>

After the Applications are created, ArgoCD will detect and manage the Yorkie addons. You can view and sync them from the ArgoCD web UI.

### Clean up cluster addons

You have now installed Yorkie monitoring, ArgoCD and Yorkie analytics, and viewed Yorkie metrics on Grafana dashboard and Yorkie GitOps on ArgoCD web UI.

To learn about how to configure Yorkie Monitoring in Helm Chart, see [Yorkie Chart Repository](https://github.com/yorkie-team/yorkie/tree/main/build/charts/).
For ArgoCD configuration, see [argo-cd chart documentation](https://github.com/argoproj/argo-helm/tree/main/charts/argo-cd).

First, uninstall ArgoCD with the following command:

```bash
# Uninstall ArgoCD helm chart releases
$ helm uninstall argocd-apps -n argocd
$ helm uninstall argo-cd -n argocd

# Delete ArgoCD CRDs
$ kubectl get crd -oname | grep --color=never 'argoproj.io' | xargs kubectl delete

# (Optional) Delete ArgoCD namespace
$ kubectl delete namespace argocd
```

Then, uninstall Yorkie monitoring with the following command:

```bash
# Uninstall Yorkie monitoring helm chart release
$ helm uninstall yorkie-monitoring -n monitoring

# Delete monitoring CRDs
$ kubectl get crd -oname | grep --color=never 'monitoring.coreos.com' | xargs kubectl delete

# Delete monitoring service accounts
$ kubectl delete serviceaccounts --all -n monitoring

# (Optional) Delete monitoring namespace
$ kubectl delete namespace monitoring
```

Then, uninstall Yorkie analytics with the following command:

```bash
# Uninstall Yorkie analytics helm chart release
$ helm uninstall yorkie-analytics -n analytics
$ kubectl delete namespace analytics
```
